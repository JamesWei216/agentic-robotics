# 码垛套件 `libero_wood_stack` 设计说明（加分 c：码垛 ↔ 分拣切换 + 改动成本可量化）

> 目标：证明**同一套 Agent 框架**（任务书 → LLM 计划 → LLM 生成代码 → 仿真执行 → 固定 seed 评测 → 诊断/修复 → 报告）
> 能在"分拣"与"码垛"两类任务之间切换，并把切换成本量化成可核对的数字。
> 新增能力只落在"技能层 + 任务定义"，**编排层、执行层、评测层、安全层、人确认层零改动**。

---

## 1. 工作单元

| 项 | 值 |
|---|---|
| 平台 | LIBERO（MuJoCo），Franka Panda + 平行二指夹爪，桌面 z = 0.90 m |
| 物料 | `wood_block` 40 × 40 × 40 mm 木块（程序生成，密度 800 kg/m³ ≈ 51 g，摩擦 1.0/0.005/0.0001） |
| 相机 | `agentview` 256×256 + `robot0_eye_in_hand` 256×256 |
| 堆叠区 | \|x\| ≤ 0.07 m，y ≈ 0.10–0.13 m（基块区域 jitter ±20 mm） |
| 取件区 | -0.15 ≤ x ≤ +0.09 m，y ≈ -0.13 – -0.02 m（jitter ±20 mm） |
| 成功判定 | LIBERO 原生 `On(top, base)` 谓词：底块 z ≤ 顶块 z + 几何接触 + 两中心 xy 距离 < 30 mm（**无自写判定脚本**） |

### 垛型（3 种，由任务协议下发，Agent 代码零改动）

| 任务 | 垛型 | 目标谓词 |
|---|---|---|
| t0–t4 | 3 层直塔 | `On(b2,b1) ∧ On(b3,b2)` |
| t5–t9 | 2 层塔 | `On(b2,b1)` |
| t10 | 双层双列（长程，4 次放置） | `On(b2,b1) ∧ On(b4,b3)` |

每个任务 50 个固定初始状态（`scripts/gen_init_states.py`，seed 公开；与分拣套件同协议）。

| 口径 | 套件 | 结果 | 平均步数 |

| **LLM 全链路**（DeepSeek 出计划 + 出代码，AST 白名单校验通过） | 4 任务 × 2 seed = 8 episodes | **8/8 = 100.0%** | 618 步 / 5.8 s |

放置精度（脚本专家逐次落点）：xy 偏差 0.5–8.4 mm，落点高度恒为 1.0 个块高（40.0 mm），远好于 `On()` 的 30 mm 判据。

## 4. 实现要点

1. **抓取高度**：抓木块底面以上 12 mm，不是几何中心。中心高度（桌面 + 136 mm）会让 Panda 肘关节
   `j4` 顶到 -0.07 rad 限位（手臂伸直），此后笛卡尔控制器**无法回缩**（见 A16）。
2. **运输路线**（`place_on_top`）三选一，按顺序尝试、以"到位距离 ≤ 30 mm"为够用判据：
   `home_center`（回到 reset 位姿再横移）→ `bent_arm`（先降到桌面 +0.10 m 的半屈臂位姿）→ `direct`。
3. **释放**：EE 位于"目标顶面 + 22 mm + 半个块高"，因为指尖会低于工件底面（A18）；
   释放后竖直撤离，再 settle 40 步让木块落平。
4. **判定**：局部校验 `_stack_ok`（xy ≤ 20 mm、dz = 40 ± 12 mm）只用于决定是否重试；
   任务成败一律由仿真 `On()` 谓词给出（`R.check()` / episode done）。

## 5. 踩过的坑（A16–A21，已写进 `docs/failures.md` 口径）

| 编号 | 现象 | 根因 | 修法 |
|---|---|---|---|
| **A16** | 第 2/3 次放置横移停在离目标 115–135 mm 处，所有路线误差完全相同 | 抓取点在木块几何中心 → EE 高度 1.036 m，肘关节 `j4` 顶到 -0.07 rad 限位（手臂伸直）→ 笛卡尔控制无法沿"缩回"方向运动（雅可比奇异） | 抓取点下移到桌面上方 12 mm（`grasp_h=0.012`），`j4` 回到 -1.2 ~ -1.6 |
| **A17** | 右侧 x = +0.13 的工件抓取后一律放不到位（q4 = -0.115） | 工作空间"舒适带"边界：机器人基座在 x ≈ -0.21，右侧远格超出手臂可用伸展 | 工位重设计：取件区 `-0.15 ≤ x ≤ +0.09`，堆叠区 `|x| ≤ 0.07` |
| **A18** | 10 mm 释放间隙下木块歪在底块边缘（dz = 20 mm） | 指尖低于工件底面，先于工件触到底块顶面 | 释放间隙 10 → 22 mm |
| **A19** | 运输高度按"桌面 + 0.32 m"算，第三块塔（目标顶面 0.98 m）不可达 | 运输高度必须由**当前堆垛高度**推出：`top + 半个块高 + 0.06` | 同上 |
| **A20** | 一旦 `j4` 已被顶到限位，后续任何路线都救不回来 | 控制器在奇异位形下无法产生"回缩"方向的速度 | 路线顺序固定为 `home_center` 优先，不做"先试直连再补救" |
| **A21** | `gen_missions.py` 把 `(:init (On obj region))` 也当成目标，且正则把右括号吞进物体名 | 复用分拣正则时未区分 init/goal | `[^\s()]+` + 过滤 `*_init_region` |

这些问题**都不是"策略不会做"**，而是"工位/几何/控制器边界"问题——与分拣套件的 A6/A11/A12/A13 同类，
是仿真码垛最容易踩、也最值得写进文档的部分。
